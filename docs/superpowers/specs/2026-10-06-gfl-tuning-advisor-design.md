# Gridcraft GFL 整定优化：设计规格 v1

**状态：用户已确认设计范围；实施计划待审阅。未修改生产代码，未发布。**  
**代码基线：`8897496aa6b66aca2d8def4337e96c735054edaf`**  
**回归案例：用户提供的 `PV_Grid_Demo.json`，PV1，Vdc/Vac，considerScr=true。**

## 1. 目标与边界

服务于纯浏览器中的 HIL 系统前期设计。帮助用户判断目标是否可实现、为何受限，并给出可解释的 PI 候选，而不是要求用户事先知道正确的交越频率。

本轮只优化现有 GFL 的整定诊断、候选搜索、结果评价和确认应用。保留现有电气模型与标幺定义。不增加 PLL、完整 dq 耦合、GFM 新算法、EMT、FRT、STATCOM、MMC、DC-DC 或频率分布图。P–Q 能力图是另一个独立任务。

用户导入的工程、RLC、测量滤波、DC 电容、DC 电压、控制周期与延时默认视为固定事实；本轮只允许搜索 PI。参数敏感性试算不能自动写回这些事实。

成功标准不是“必须显示 50 Hz”，而是：可实现的目标给出经过声明模型校核的候选；未达到目标时明确说明；输入不足或模型不覆盖时不伪装为通过；旧工程可以复现原参数。

## 2. 本案例的已确认基线

上传文件与当前整定算法的 8 个 Kp/Ki 值逐项完全一致。JSON 中的 `ki` 是并联 PI 的 Ki，不是界面显示的 Ti；当前界面采用 `Kp + 1/(Ti*s)`，因此 Ti=1/Ki。

| 项目 | 数值 |
|---|---:|
| S / VLL / f0 | 1 MVA / 315 V / 50 Hz |
| 工作点 | P=1 MW，Q=0 |
| 逆变器 Rf / Lf | 1 μΩ / 63 μH |
| PCC 串联 RC 支路 | 0.051 Ω / 1500 μF |
| DC 端电压 | 800 V |
| Vdc 分析电容 | 独立分析总电容 64 mF |
| 控制周期 | 50 μs（fs=20 kHz） |
| 显式纯延时 | 0 个控制周期 |
| 电流测量滤波 | 1 ms |
| Vdc 与交流电压测量滤波 | 各 10 ms |
| SCR / X/R | 2.1167486210 / 9.4753219390 |
| 目标内环 / 外环交越 | 500 / 50 Hz |
| 实际 d、q 内环交越 | 7.2122177636 Hz |
| 实际 Vdc / Vac 外环交越 | 1.4424435527 / 1.4424435527 Hz |

两级变压器已具有 Rpu=0.001、Xpu=0.1，不能按早期“理想变压器”讨论忽略。P/Q 内部键在当前模式分别指 Vdc/Vac。

固定策略：PM>=60°；内环零点比 r=Ki/(Kp*ωc)=0.2；Vdc r=0.2；Vac r=5；外环交越不得超过实际内环的 1/5。交流电压滤波 Hv 同时影响 SCR 内环的电压前馈残余和 Vac 反馈，不只是外环上的一阶环节。

## 3. 首先修正流程，不只修正数学

### 3.1 分离“评估现有 PI”和“搜索新 PI”

现有 UI 的 refresh 先执行 autoTuneGfl；自动整定失败会进入 invalidate，可能连手动 PI 的频响也清空。新版必须拆分：

1. 读取/校验工程上下文。
2. 在输入可建模时评估当前已保存或手动 PI。
3. 用户请求时独立执行候选搜索。
4. 搜索失败不影响已保存 PI 的分析与导出（前提是该 PI 本身合法且模型可计算）。

### 3.2 不能静默替换导入参数

旧版 manual=false 会在打开页面时重新生成 PI。新算法引入后，不能因此改变既有 HIL 工程的增益。

无新整定版本标记的旧工程：加载并保留原增益；显示“旧策略结果 / 新版尚未应用”。分析可以自动刷新，但“应用候选”必须是明确动作。新工程允许使用自动推荐作为默认模式，但首次应用仍可预览。

### 3.3 保留可实验性

不把电流能力超限、低裕度、极弱网统一当作禁止保存的错误。HIL 用户可能故意测试这些情况。可以保存和比较，但不纳入“推荐候选”或自动应用。NaN、无意义单位、选定模型要求的非正电容等才属于基础输入无效。

## 4. 输入、目标和状态

### 4.1 输入分层

- **已知事实**：额定量、实际 RLC、频率、工作点、DC 电压、DC 电容来源、测量滤波、控制执行周期、已配置延时。
- **可整定量**：本轮允许修改的 Kp、Ki；默认同一电流环对象下 d/q 使用同一策略，但结果仍分别核验。
- **设计目标**：交越、裕度、超调、稳定时间、扰动恢复。没有明确任务要求的项目应保持未设置，不伪造“用户要求”。
- **试算条件**：暂时的参数覆盖，与主工程数据分离，显式标记来源。

控制周期 fs 与滤波设计中的开关频率 fs 是不同字段语义。UI 统一标为“控制频率 fctrl”和“开关频率 fsw”，内部兼容旧键。不得把 20 kHz 的控制执行频率解释为 2 kHz 的 PWM 频率。纯延时 0 表示用户模型设为零，不表示真实 HIL 链路无延时。

### 4.2 自动推荐模式

不强制用户填写交越。提供均衡/参考跟踪/扰动恢复侧重，详细目标可以留空。使用明确标注的工程预设进行候选比较，并展示预设值，不冒充 IEEE/国标要求。

推荐频率不是算法扫到的最大值。只在模型校核与用户硬约束通过的候选中，按实际时域跟踪、扰动恢复及鲁棒性评价排序。用户未提供扰动或不确定范围时，不作“抗扰已验证”或“鲁棒”结论。

最多展示几组不被其他候选全面优于的代表解；无需强行凑齐三个方案。每组说明获得什么、牺牲什么。不存在明显更优解时明确说明。

### 4.3 指定交越模式

输入目标交越、允许误差、是否允许降频、最低接受频率、优选裕度、最低允许裕度，以及可选的超调/稳定时间上限。

优先级为：模型稳定性与硬约束 > 目标交越 > 优选裕度及其他软目标。不能为了实现 50 Hz 突破最低裕度或静默改动物理参数。

若 user 要求最低 40 Hz，不得返回 1.44 Hz 并标记“满足要求”。可以同时展示一个较慢、已筛查的备用候选，但它的状态必须是“未满足速度要求”。

### 4.4 结果状态

建议用正交字段，避免一个绿色灯混合所有概念：

- inputStatus：valid / invalid / incomplete
- modelCoverage：exactZeroDelayScalar / frequencyOnlyWithDelay / unsupported
- searchStatus：notRun / feasibleFound / targetNotMet / noCandidateFound / budgetExceeded
- targetStatus：satisfied / partiallySatisfied / notSatisfied / notSpecified
- applicationStatus：baseline / preview / applied / stale

只在全部被要求的硬约束完成评估且通过时称为“当前模型满足目标”。搜索未找到只说明当前模型、控制器族、搜索范围和数值预算内未找到，不宣称所有算法或物理系统绝对不可实现。

## 5. 搜索与校核原则

### 5.1 保留旧算法作回归基线

原 autoTuneGfl 行为保持可回归；新策略采用独立入口。导出必须包括 policyId、版本、基线提交、输入摘要与模型假设。不能只靠显示文案区分算法。

### 5.2 解除固定零点比，但保留完整检查

对给定交越 ωc 和 r=Ki/(Kp*ωc)，用当前有效对象 Geff(jωc) 构造：

Kp = 1 / (|Geff(jωc)| sqrt(1+r²))

Ki = r*ωc*Kp

此公式只保证指定频点的开环幅值为 1，不能单凭该点判断稳定。候选需要遍历实际频响、发现全部交越、校核闭环。若保留纯 P 作为边界诊断，它不能冒充满足积分跟踪和扰动要求的 PI。

先在目标附近搜索零点比，找不到才按授权降低频率。自动推荐时联合搜索频率和零点比。采用粗扫加局部细化、缓存与预算控制；预算耗尽应显式返回，不形成假“不可行”。

### 5.3 级联必须使用实际内环

先生成若干合格内环候选，分别闭合后供外环设计，而不是只选一个内环然后声称外环的结果就是最优。Vdc 和 Vac 的实际外环交越可以不同。

默认保留现有 5 倍间隔作为“工程策略”，便于对照。允许专家设置其他值，但必须继续校核级联闭环；UI 不把该值当物理定律。不能用用户输入的 fi 代替实际内环交越。

### 5.4 全部交越与稳定性

- 扫频范围与候选目标关联，包含目标以下足够频段，避免低于 0.1 Hz 的交越被现有固定图域遗漏。
- 相位连续展开；不能只对单点 principal angle 强行加减 360°。
- 显示全部上/下穿 0 dB 的交越。多交越不是必然不稳定，但第一版保守策略可以排除推荐；状态应解释“本策略不推荐”，而非无效输入。
- 本案例零延时：沿用当前标量闭环多项式，并通过有尺度归一化的数值方法验证根/稳定性。不得仅依赖相位裕度。
- 非零纯延时：保留 exp(-sTd) 的频域分析。未完成对应延时系统稳定性验证时标记 frequencyOnlyWithDelay，不输出“整体稳定已验证”。不能把零延时多项式结果套到有延时系统。
- 控制周期目前只提供频率范围和延时换算，不等于已经包含 ZOH 或精确离散 PI。保持这条模型边界可见。

### 5.5 时域评价

零延时下建立与现有物理输出 T(s) 一致的小信号线性模型，报告：10–90% 上升时间、相对最终值的超调、±2% 稳定时间、相对 DC 增益的首个 -3 dB 带宽及额外交点。

评价实际量和滤波测量量时必须分别标注；不能把滤波后的“更平滑”误当成实际输出已稳定。响应观察窗自适应；未在窗口内稳定标成未稳定，不用最后一个采样点作为最终值。

积分增益不能为了 PM/fc 被任意压小而不检查恢复时间。参考跟踪快不等于扰动恢复快。第一版扰动项只在定义了注入点、符号、幅值和可用传递函数后开放；未建模的扰动不显示合格。

线性阶跃是围绕额定点的小扰动归一化分析，不模拟大阶跃的饱和、限流、积分饱和、PWM 或 HIL 故障。PV1 为额定点标量模型，P/Q 的修改目前不重新进行完整工作点线性化，结果中必须说明。

## 6. 诊断输出的具体内容

以本案例输出：

1. 当前实际内环仅 7.212 Hz，而非目标 500 Hz。
2. 已启用电网 R/L 与 RC；交流电压的 10 ms 滤波影响前馈残余。
3. 固定内环零点比 0.2 与 60° 策略首先限制内环；这不是硬件的绝对带宽上限。
4. 外环被实际内环的 1/5 限制为 1.442 Hz；Vdc/Vac 当时仍分别有约 69.1°/91.7° 裕度，不能声称二者都被各自 60° 边界卡住。
5. 同一电气及滤波参数下，诊断探测的内环 50 Hz、r=0.05 可获得约 61.69° 裕度，并通过此零延时标量模型的校核；这证明固定比例策略存在优化空间，不证明外环 50 Hz 可行。
6. 对应探测中的 Vdc 外环约 5.188 Hz、Vac 外环 10 Hz。Vdc 超调也上升，不能只按速度宣布更优。

敏感性比较必须给出“只改了什么”：例如仅改变 Vdc 反馈滤波，在当前旧策略下不提高外环交越，因为内环/5 仍是限制；仅减小电流滤波可能触发额外交越检查。不要生成“滤波越小、带宽必然越高越好”的误导。

## 7. 模型和输入的一致性提示

- 上传网络 DC1 为 800 V 理想源、Rdc=0；Vdc 整定设置为独立 64 mF 电容及恒定 DC 输入功率模型。两者不是同一套 DC 动态。保持选择不变，但增加提示，不能把 Vdc 分析结果直接称为该理想源电路的时域响应。
- 独立分析电容不是硬件电容自动更新，不从 dcCapDesign 的未应用参数强行覆盖。
- 10 ms 交流电压滤波目前被前馈与 Vac 反馈共用。第一版保持此语义；分离这两个参数需实际控制结构依据及独立兼容设计。
- 没有 Imax、实际 PWM 延时等信息时，相关检查显示未配置，不从额定电流或执行周期推断硬限制。

## 8. UI 与持久化

保留现有入口、页面、Bode、增益编辑和单位习惯。在整定区增加模式选择，结果区显示：用户目标 → 当前结果 → 候选结果 → 未满足条件 → 主要限制原因。

按钮含“分析当前参数”“生成候选”“与基线比较”“应用所选候选”。参数改变后旧推荐标记过期；计算使用输入快照编号，异步旧结果不能覆盖新结果。

应用候选只修改已授权的 PI 与整定元数据，不动 RLC、DC 电压、滤波、工作点或其他逆变器。继续保持项目同步；原未知 extensions 必须保留。已应用结果可恢复原增益。

不因自动推荐失败而清空合法手动 PI 的图或禁止分析。若数学输入本身无效，则清除/灰显失效结果，并明确原因。

## 9. 模块边界（建议）

- 工程上下文适配：从现有 project/gfl-settings 与 outerContext 提取纯输入，复用单位换算。
- gfl-tuning-diagnostics：参数来源、目标与约束、限制原因、覆盖状态。
- gfl-tuning-search：PI 候选与搜索策略，返回结构化结果而非靠异常表示目标未达。
- gfl-linear-evaluation：频响、多交越、零延时极点/物理输出线性指标。
- ui/gfl-design：仅负责状态机与展示，剥离自动搜索失败对手动评估的阻断。

优先复用已有复数、多项式与显示工具。缺失数值能力应先核对可用成熟实现，不能直接用未验证的高阶根算法上线。开发期的独立 SciPy 对照不成为在线依赖。

## 10. 验收条件

1. 原始 PV1 所有参数、8 个 PI 数值和旧策略交越可重复重现。
2. 导入旧工程不会自动改用新算法覆盖已保存增益。
3. 目标 500/50 与实际 7.212/1.442 必须明确区分。
4. r=0.05、内环 50 Hz 的探测能被候选搜索发现或存在清晰的额外约束淘汰原因，不能仍仅固定 r=0.2。
5. 50 Hz 外环未达成时明确报目标未达；不能只显示模型稳定就当成目标达成。
6. 未知滤波、延时、电流上限与已知为 0 的值区分。
7. 多交越、有延时、极低目标、R=0、滤波旁路、P/Q 与 Vdc/Vac 模式分别回归。
8. 自动搜索失败不阻止合法手动 PI 的评估。
9. 频域传递函数和线性阶跃/极点对象一致，物理输出与传感输出明确。
10. 导出含目标、限制、模型、算法版本、候选状态和实际应用状态。
11. 本轮不修改非 GFL 模块，不引入在线服务器或运行时 Python 依赖。
12. 完整集成后才能宣称全仓测试、构建或浏览器交互通过；当前诊断包的 12 项检查不替代它们。
